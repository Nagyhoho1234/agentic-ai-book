# Chapter 11: Future Directions

## Summary

The final chapter looks forward, discussing advanced prompt patterns, current limitations of AI coding tools, and what the future may hold. It is shorter and more speculative than the preceding chapters, serving as a capstone and an invitation to continue learning.

### Prompt Patterns

The chapter introduces advanced ways to interact with AI coding assistants:

- **Flipped interaction pattern:** Instead of you asking questions, you ask Copilot to ask YOU questions. For example: "I need a Python function to process my data. Ask me questions about the data format and what I need." This can help you think through requirements you might have missed.
- **Persona pattern:** Ask Copilot to adopt a specific role or expertise level. For example: "Act as an expert data scientist and review this code" or "Explain this as if I am a complete beginner." Different personas produce different styles of output.
- **Recipe pattern:** Ask for a step-by-step plan before generating code. For example: "List the steps needed to clean and analyze this dataset, then write the code for each step."

### Current Limitations

The chapter honestly discusses what AI coding tools cannot do well (as of 2023):

- **Correctness is not guaranteed:** AI-generated code can be subtly wrong. The programmer must always verify.
- **Training data has a cutoff:** Copilot does not know about libraries or APIs released after its training data was collected. It may generate code using deprecated functions.
- **Context window limitations:** Copilot can only see a limited amount of code at once. It may miss important context from other parts of your project.
- **Inconsistent behavior:** The same prompt may produce different code on different occasions. This is inherent to probabilistic models.
- **Difficulty with novel or unusual tasks:** Copilot works best for common programming patterns. Highly specialized or novel tasks may require more manual intervention.
- **Security and licensing concerns:** Code generated by AI may inadvertently reproduce copyrighted code or introduce security vulnerabilities.

### What May Come Next

The authors speculate on future developments:
- More powerful models with larger context windows
- Better integration with development environments
- AI tools that can understand entire codebases, not just individual files
- AI-assisted debugging and testing
- Natural language programming becoming more accessible to non-programmers

## Key Techniques for AI-Assisted Coding

- **The flipped interaction pattern:** Let the AI ask you questions to help refine your requirements. This is particularly useful when you are unsure how to specify a complex task.
- **The persona pattern:** Assign the AI a role to get output tailored to your needs -- an expert for advanced code, a teacher for explanations, a reviewer for code quality.
- **The recipe pattern:** Get a plan first, then implement. This mirrors the top-down design approach but uses the AI to help with the planning step.
- **Stay current:** AI tools are evolving rapidly. Techniques and limitations described in any book (including this one) may change as models improve.

## Practical Takeaways for Scientists

- The flipped interaction pattern is excellent for scientific computing: "I have a dataset of geochemical measurements. Ask me questions about the format and what analyses I need." This surfaces requirements you might forget.
- The persona pattern lets you get domain-specific help: "Act as a geophysicist and suggest appropriate analysis methods for this seismic data."
- AI tools will continue to improve, but the fundamental skills taught in this book -- problem decomposition, testing, code reading, clear specification -- will remain valuable regardless of how capable the tools become.
- The human judgment about what to compute, how to interpret results, and whether the output makes scientific sense cannot be outsourced to AI.
