# Chapter 14: Surviving As a Software Engineer

## Summary

This chapter addresses the career implications of AI coding tools for software engineers, arguing that the disruption is evolutionary (like automotive industry automation) rather than catastrophic (like switchboard operators being replaced). Wienholt draws the Charles Darwin analogy: survival depends on adaptability, not strength or intelligence.

The "Five-Tool Software Engineer" concept is central: like a five-tool baseball player, a valuable engineer codes quickly, codes with minimal errors, has strong industry knowledge, works effectively with stakeholders, and is skilled in production deployment and support. AI tools currently address only the first tool (coding speed). Engineers who develop all five tools will be the survivors.

The chapter provides concrete career guidance:
1. **Lead the AI transition** rather than resist it -- reformulate specifications for AI consumption, codify architectural conventions into Copilot custom instructions, and introduce nonfunctional requirements into the development process
2. **Pass the recruitment hurdle** -- a leaked recruiter criteria list shows the industry increasingly values formal qualifications from elite universities, 4-10 years of experience, startup background, and explicitly excludes candidates from legacy IT companies and coding bootcamps
3. **Pursue growth areas** including integration engineering, production support, and working with business stakeholders
4. **Be skeptical of hype** -- the chapter includes a devastating list of failed technology predictions (iPhone will fail, the metaverse, NFTs, "machine learning code generation is 5-10 years away" from Gartner in 2022)

The integration engineering section argues that AI coding tools increase demand for engineers who can manage system interfaces, resolve edge cases in distributed systems, and stabilize code bases against the "whack-a-mole" effect of AI-generated fixes.

## Key AI Coding Techniques

- **Custom Copilot instructions for teams**: Codify architectural conventions and coding standards into instruction files that guide AI-generated code
- **Nonfunctional requirement scanning**: Use Copilot to regularly review code for security, performance, and usability issues
- **Production support with AI**: Use LLMs to analyze log files, suggest fixes for specific error messages, and generate monitoring code
- **Specification-to-code pipeline**: Position yourself as the bridge between business requirements and AI-implementable specifications

## Practical Takeaways for Scientists

- **Develop all five tools, not just coding speed** -- domain expertise (the "industry knowledge" tool) is your strongest asset as a scientist who codes
- For scientific software, production deployment and support skills are increasingly valuable as research software becomes operational
- Integration engineering skills matter for scientific workflows that connect instruments, databases, analysis tools, and visualization platforms
- Use AI to upskill in areas outside your core expertise -- let Copilot help you learn DevOps, testing, or infrastructure management
- Open source contributions on GitHub can flesh out a resume and demonstrate AI-assisted coding skills
- Be wary of predictions about AI replacing scientists/developers -- similar predictions have been wrong many times before
- Junior scientists entering the field should focus on domain expertise and stakeholder communication, not just coding -- these are the hardest skills for AI to replicate
- The "boring but useful" approach wins long-term: like bitcoin vs. NFTs, practical applications of AI tools will outlast flashy but impractical ones
